Toolbar at the bottom — tldraw / draw.io / FigJam iPad all put creation tools within thumb reach; the top bar keeps only a menu + undo/redo + a help button.
Bottom sheets for palette and inspector (partial height so the canvas stays visible). Built with React Flow's <Panel position="bottom-center">.
iOS Safari: dvh not vh; bottom bar needs padding-bottom: env(safe-area-inset-bottom, 0px) + viewport-fit=cover or it is unusable behind the home bar.
First touch = view-only consideration (Miro's mobile pattern) so a new user's first pan can't move the diagram.
Build order (lowest risk first): 1) one useEditorInterface() hook (measures the CONTAINER, not the window — critical for an embeddable tool) → 2) desktop panel collapse + persistence → 3) touch hardening (works at all sizes, testable in DevTools emulation) → 4) tablet tier → 5) phone tier.

Not shown here: the touch changes are behavioural (long-press, thresholds, hit areas) — they don't change the layout, so they're verified by interaction, not by a mockup.
